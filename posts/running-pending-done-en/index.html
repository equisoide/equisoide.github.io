The most expensive problem of working with several agents is not that they make mistakes. It is that they lose the thread between each other.

I have spent months running AI agents in parallel on the same project: one session opens work, another picks it up hours or days later. The real cost was never bad reasoning. It was the context that falls through the cracks between one session and the next.

The solution ended up being boring on purpose: three folders.

Running/today's session, in progress.
Pending/it ended leaving work half done: someone else picks it up.
Done/it ended with nothing pending.

Two rules make this actually work:

  1. On closing, the agent itself decides the folder, without waiting to be asked. If something is left half done, it goes to Pending/ with what is missing written at the top, in first position.
  2. Inside, nothing is summarized: everything is written. What was measured, what was discarded and why, what went wrong. The session is not opened by the one who lived it.

The effect I did not expect: this made the handoff between agents trivial. Passing work from one to another stopped being copying context by hand or re-explaining from scratch. Now it is pointing at the file in Pending/ and continuing exactly where it left off.

Is it a new idea? Honestly, not entirely: memory banks, checkpointing, handoff notes, the concept is already out there. What I do think is worth sharing is the execution: forcing the closing decision instead of leaving it floating, and forcing everything to be written down instead of a tidy summary. That is exactly where most handoff patterns fall short: the elegant summary is the first thing to lose the detail the next agent needs.

And it does not compete with spec-driven development: they complement each other. The spec says what has to be built; the log says where the one building it left off, what it measured and what it discarded. One prevents drift; the other prevents starting from zero.

If you are building with several agents and feel the context slipping away between sessions, try this before anything more sophisticated.

Want to try it in your own workspace? Paste this to your agent:
Prompt for your agent
Create a Sessions/ folder with three subfolders: Running/, Pending/ and Done/.

Running/ holds today's session, in progress.
Pending/ holds sessions that ended with work half done, so another session can pick them up.
Done/ holds sessions that ended with nothing pending.

Rules I want you to follow:

1. At the start of any session, create a new file in Running/ named YYYY-MM-DD-topic-in-kebab-case.md.

2. Write everything in that file as you work: details, notes, measured numbers, what you discarded and why, what went wrong. Do not summarize: whoever opens it later did not live the session.

3. On closing, decide the destination folder yourself, do not wait for me to ask. If something is left half done, move the file to Pending/ with what is missing written at the top, in first position. If nothing is pending, move it to Done/. Tell me in one line which folder it went to and why.

4. When opening a new session, check whether there is a file in Running/ with a date other than today. If there is, it is a session that ended without closing: ask me whether it goes to Pending/ or Done/ before starting yours.
